Chronicle Shell Redesign

Campaign interface — Paradox-style HUD, grouped ledger menus and the World Ledger rail · design + implementation report

The campaign's content was already rich (heraldry, T-accounts, why-chains, year chronicles) — what it lacked was information architecture and hierarchy. Twenty independent floating windows hung off a flat 16-chip strip; the campaign clock sat buried in a 220px worldgen leftover; nothing said "you are playing a living world" at a glance. This pass applies the three moves every Paradox title uses: a persistent top HUD (date · speed · world pulse · alerts), grouped screens instead of a chip soup, and one shared design language (tokens in src/ui/chronicleTheme.ts).

Type: campaign headings and the date use the serif stack 'Iowan Old Style' / Palatino / Georgia — the "chronicle voice"; body and data stay in the app sans for density. Gold is reserved for identity moments (dates, mastheads, season progress, active ◉ dots) so it stays special.

4 · Interaction & architecture notes

ChangeWhy
Clock moved into campaignStore (playing / speed / auto-advance loop) Exactly one loop ever runs; any surface (HUD, rail, future hotkeys) can drive or reflect it. Pausing still refreshes panels and flushes the sim to disk.
Space = pause/playThe strategy-game reflex. Ignored while typing in inputs.
Forge keeps WindowBar; Chronicle gets the HUDThe two subproducts now read differently at a glance — build tool vs. living game.
Starving alert tile appears only when > 0Alerts earn their pixels; a permanent zero is noise.
Menus close on outside click, ◉/○ state dots, open-count badgesThe bar shows what's open without opening anything.
Next phase (proposed): migrate the floating windows' headers to the shared chrome (serif title + tint + unified tab row via chronicleTheme.ts), then an EU4-style outliner mode for the rail (pinned cities/houses/wars) and map-mode buttons in the HUD.
